# Maintain Control Plane

## Workflow

1. Start with the active task/status registry and the owning source. Load only the affected requirement, plan, test, eval or evidence section.
2. Search RUNLOG by task, policy or evidence ID when history is material; do not read the full RUNLOG in ordinary use.
3. Read the PRD or roadmap only when product meaning, scope, milestone or acceptance changes. Read TEST or EVALS only when verification strategy, eval semantics, thresholds or evidence status changes. Read the relevant [team contract](../../../docs/plan/plugin-v1-team-contracts.md) only when ownership, handoff or runtime boundaries change.
4. Trace requirement -> task -> exact owner/skill -> case -> evidence for the affected path. Preserve current versus deferred local/remote scope.
5. Update one active summary or canonical link. Do not copy machine-readable constants into multiple prose surfaces, rewrite dated completion reports or modify append-only RUNLOG history.
6. Distinguish accepted contracts, implemented source, static checks, loaded behavior, runtime/browser results and human usefulness. Never promote one into another.
7. Validate only affected references, requirement maps, ownership, cases and focused checks. Stop after the smallest sufficient evidence; provide useful partial results when a claim or action remains unsupported.

## Output

Return exact owned files or findings, the affected requirement/contract mapping, observed checks and failures, evidence limits, rollback, risks and next owner. Stop on unsafe data, missing applicable acceptance, ownership conflict or action outside existing authorization; do not invent evidence.
