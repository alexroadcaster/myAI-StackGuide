Условно рекомендую оценить [Firecrawl](https://github.com/firecrawl/firecrawl) для поиска веб-страниц и получения их содержимого в Markdown/JSON; [Firecrawl MCP Server](https://github.com/firecrawl/firecrawl-mcp-server) имеет отдельную роль адаптера и нужен лишь при подтверждённой потребности в MCP. Предоставленные чтения README от 2026-10-11 подтверждают эти возможности, но пригодность для проекта остаётся неизвестной. Каталог — снимок от 2026-09-01; чтения хоста его не обновляют. Firecrawl учитывается один раз независимо от вторичных категорий и прежнего имени `mendableai/firecrawl`. Это устранение повторов рекомендаций; дедупликация получаемых документов не подтверждена.

Предлагаемая связь компонентов: приложение → необязательный MCP-адаптер → Firecrawl → нормализация и приём данных приложением. Поиск и извлечение покрывает Firecrawl; контракты данных, дедупликацию, происхождение документов, очередь, хранение и обработку ошибок должна определить команда. Основное ядро преимущественно использует AGPL-3.0, SDK и некоторые UI-компоненты — MIT; лицензия адаптера в снимке — MIT. Облачные примеры ядра требуют API key. README адаптера описывает размещённые scrape/search/parse без ключа с ограничением частоты, но crawl/map/agent требуют ключ; отсутствие ключа не устраняет сеть. Настраиваемый адрес собственного API не доказывает равенство возможностей самостоятельного размещения и облака. Для текущего сценария без сети возможна лишь изолированная оценка контрактов и предоставленных источников.

Единственный сценарий планирования — первая проверка: гипотетически 4–8 инженерных часов, уверенность низкая; один инженер, знакомый с целевым приложением и интерфейсом компонента, при 8 часах на инженерный день. До любой интеграции требуется подтвердить нагрузку, существующий путь, язык/платформу, выбранную версию и лицензию. Предлагается только синтетическая проверка или оценка источников, без установки, учётных данных, платного провайдера и производственных данных. При одинаковом объёме поиска и извлечения Firecrawl потребует интеграции, проверки зависимостей и сопровождения обновлений; собственная реализация — разработки и поддержки этих функций; существующий или встроенный путь неизвестен и требует сравнения. Экономия не установлена. Сложность меняют рендеринг страниц, качество извлечения, лимиты, размещение и лицензирование; полные трудозатраты внедрения и календарная длительность неизвестны.

Все следующие шаги имеют статус `proposed_not_executed`: на изолированной синтетической выборке предложено проверить ожидаемые Markdown/JSON, ссылки на источники и правила обработки повторов, затем сравнить одинаковые критерии с существующим путём, когда он будет установлен. Такая проверка не докажет работоспособность Firecrawl или активацию MCP; интеграция требует отдельного явного запроса. Предпочтение следует пересмотреть, если нужные возможности недоступны в допустимой конфигурации, лицензия не принята или существующий путь удовлетворяет тем же критериям с меньшими затратами. Поскольку текущий путь неизвестен, пробу следует держать отдельно, без изменения авторитетных данных и очереди; отказ от неё сохраняет исходное состояние.
