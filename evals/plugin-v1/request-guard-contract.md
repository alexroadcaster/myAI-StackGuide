# CP-04 recommendation-request boundary

The accepted owner continuation adds a development-only request envelope around
the existing C9 query. It contains positive query/intent, explicit numeric product
exclusions, normalized dependency exclusions, and unresolved decisions with a
question and alternatives. Codex/interview supplies this interpretation. This
module validates/preserves it; no free-text parser, model or installed-plugin
activation is claimed. Existing C9 schemas/pins/index remain unchanged.

Material unresolved decisions yield `needs_clarification` before retrieval or pack
construction. A ready request filters explicit products and source-documented
dependency conflicts before the final detailed pack, preserving surviving order
and refilling from the bounded ranked pool. Exclusion names never become positive
search terms. All documented deployment alternatives must intersect the forbidden
dependencies to establish conflict. An available alternative is conditional and
requires verification; missing facts are unknown and never prove compliance.

Evidence is a separately pinned development registry joined to canonical numeric
IDs/names, with observation dates and public source URLs. It does not contain
case IDs, grades or desired rankings. BullMQ Python/PostgreSQL transport remains
unverified and cannot establish universal no-Redis conflict. This registry is not
new canonical public-card metadata and cannot be shipped as a hidden sidecar.

Acceptance: six negative cases have no independently known forbidden IDs in top12
or final pack; all three unresolved requests make zero retrieval calls and produce
questions without a route; twelve original scenarios/five methods and ten original
historical regressions preserve unconditioned full orders and historical metrics.
The runner separately observes the unchanged prior path and guarded path, declares
hashes before capture and retains all raw prior captures/corrections.

Commands: `python -m unittest discover -s tests -p test_plugin_request_guard.py`,
`python evals/plugin-v1/run_request_guard.py --predeclare`, then `--run`.
Full-universe quality, model interpretation/clarification and final source-grounded
answer usefulness are separate open gates. Parent CP-04 remains no_go. Rollback
removes only this additive development slice; no runtime trust change is needed.
