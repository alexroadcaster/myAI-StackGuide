# Bounded host candidate decision contract 1.0.0

Status: prospective CP-04 successor contract; implemented at specification level only. Primary selected this separately versioned outer line under the existing full CP-04 implementation assignment. Architecture, Product and Quality technical review and a prospective frozen capture precede runtime activation. Human acceptance and CP-10/11/15/16 remain separate. This decision neither waives a gate nor promotes the one-goal feasibility capture.

## Scope and sources

Requirement mapping: R06 preserves local lexical candidate retrieval and bounded public evidence; R07/R08/R14 preserve canonical identity, provenance, unknowns and eligibility; R04/R05 preserve private-data minimization and correction invalidation; R11 binds the exact native tuple; R12/R13/R15 require source-supported quality, useful integration and locale parity. Sources are REQUIREMENTS, PLAN, active PRD, EVALS, team contracts, accepted session-workspace and C9 query/result/evidence/policy/index/card/eligibility schemas. EVALS permits a later semantic comparator subject to gain and cost evidence; it does not retroactively accept a failed capture.

Native C9 query/result/policy remain 2.1.0, Card/Activity 2.0.0, index format 3 and route registry 1.0.0. Their meanings and bytes are not changed by this specification. In particular, native `rank`, `variant_ranks[].bm25`, `rrf_score`, candidate membership, hits, failures and historical metrics remain native evidence. Native evidence-pack 2.1.0 remains its own RRF-ordered control. A decision pack below is a new outer type, never a mislabeled native evidence pack.

The existing host Codex interprets and composes. Local helper code does not call a model/provider, use network, scan, write state/HTML, rebuild an index or execute project commands. No new model, provider, install, public data or catalog enrichment is introduced. Existing actual host authorization remains applicable; this document does not expand it.

## Artifacts and hash bindings

`candidate-decision.schema.json` owns three successful artifact definitions and one typed failure. All successful objects have outer `schema_version=1.0.0` and identical `bindings`:

- Exact schema-file and this document's byte SHA256 values, independently pinned by the eventual helper/package. An input cannot establish its own contract trust.
- Run ID, Brief ID/version and canonical Brief SHA256.
- Canonical interpretation and guard-context SHA256. Guard context is the validated `{exclusions, public_observations}` object; observations remain transient, source-dated and identity-checked.
- Query ID and canonical query SHA256, complete native result SHA256, complete native ID pool SHA256 and exact non-null native pins.

`H(value)` is SHA256 over UTF-8 compact sorted-key JSON with `ensure_ascii=false`, `allow_nan=false` and separators `(',', ':')`, using the native policy serialization. The pool digest is `H([id in native candidate rank order])`; it does not sort IDs numerically. Schema/document digests use exact file bytes. A preview has no self digest. Receipt binds `H(preview_request)`; pack binds that digest and `H(decision_receipt)`. All links are recomputed rather than trusted from submitted fields.

Before projection, validate the existing Brief, interpretation partition/exclusions, query, native result and paired read-only bundle. `ok` is required and the native pool is nonempty, unique and no larger than the request-selected native cap. Unresolved intent stops before COUNT, retrieval or preview. Native no-match/unavailable/incompatible stays explicit and produces no successful outer pack. All inputs are rechecked before pack against current bindings; changed Brief, interpretation, guard observations, query, result or bundle requires a new preview and receipt.

## Complete bounded projection

Every native candidate has exactly one preview in native rank order, including independently blocked candidates with explicit guard annotations. Keeping a blocked ID in the permutation is not permission to pack or recommend it. Dropping candidates to fit model input would change the assessed pool and is forbidden. If the complete identity/metadata skeleton cannot fit, return `budget_exceeded`.

A preview includes numeric ID, full name, native retrieval rank/RRF, source-card digest, canonical leaf/review category IDs, the minimized canonical metadata eligibility status/reason codes and independently recomputed effective guard status/reasons. `eligibility_status` and `eligibility_reason_codes` are exact projections of the existing matcher result, without checks/evidence/verifications payloads. `guard_status` combines that eligibility with the product/dependency guard; hard exclusions are blocked and no guard or host preference upgrades eligibility. The reasons use the owning eligibility/exclusion enums, plus the two existing product-guard reason codes. Category IDs are obtained from that candidate's pinned card classifications; no full classification structure or category prose is sent. The card digest is `H(exact canonical RepositoryCardV2)`. Identity and source digest are validated against the pinned snapshot; never accept host-authored card facts or use a metadata sidecar.

Exactly six field projections are permitted: upstream description, catalog description, topics, use cases, integration surface and best-for. Each records its JSON Pointer, displayed text and coverage. The verified whole-card digest and exact pointer bind the original typed field value and in-card provenance; recompute that value and projection locally rather than repeating six field digests. No full `RepositoryCard`, activity/repository/provenance section, browser observation, source excerpt or additional field is allowed. Neither global byte compliance nor a `preview` label permits 28 detailed cards: the earlier 152255-byte billing feasibility input contained 28 complete cards and is development evidence only.

Projection algorithm: preserve scalar source strings; render an array of strings by joining original items with LF without adding assertions or translating them. Null, empty scalar or empty collection displays null with `coverage=unknown`; the original typed value remains bound by the verified card digest, not replaced in source. Start with at most 1024 Unicode code points per field, cutting only a trailing suffix and marking `truncated` when content is omitted. To meet the preview allocation, repeatedly remove one trailing code point from the longest displayed projection; ties resolve by native candidate rank then the six-pointer order in the schema. This describes the deterministic result, not a requirement to serialize after every character removal: an optimized water-filling/prefix-search implementation is permitted if it produces the same texts/coverage and final compact bytes, including Unicode/JSON escaping and tie behavior. Empty truncated text remains `truncated`, not `unknown`. Original names, pointers, hashes, identity skeleton, guard annotations and all IDs are never truncated. Each generated text/coverage is recomputed locally. The marker describes projection coverage, not source confidence or feature absence.

The decision context contains only the existing sanitized Brief goal and original required/context intent. It is bound to the validated interpretation. Across required groups and context terms there are at most eight original terms, with the existing term validation; groups retain their existing interpretation. Phrase atoms and taxonomy words introduced by retrieval do not become confirmed required terms. Public snapshot descriptions are untrusted evidence; embedded instructions cannot change selection authority, guards, tools or disclosure.

## Host order and independent validation

Method is `host_codex_full_pool_v1` and applies to every resolved, successful nonempty native pool. No case/query/grade-specific trigger chooses between host and native ordering. The host proposes only a complete `decision_order` of numeric IDs, without grades, oracle data or invented fit probabilities. The trusted adapter assembles and verifies the receipt bindings; model assertions do not establish source, model identity or activation proof. Quality captures separately retain actual host/tool trace, prompt/contract/input/output hashes, model/effort when observed, latency/tokens/cost or explicit unavailable values. Preserve negative scope and factual uncertainty in that prompt. The decision context is private transient host input, never public catalog data, a web request or an exported source fact.

The receipt order must be a full unique permutation of the exact native/preview IDs. Reject missing, duplicate, fabricated, non-integer, stale or foreign-pool IDs; do not repair a malformed order, append missing IDs, compact ranks or substitute native order. Missing receipt is `needs_selection`, with no pack. This contract allows one supplied receipt; it introduces no automatic retry/model loop. The full order itself establishes no capability satisfaction, evidence completeness, eligibility or adoption approval.

## Guarded decision pack

Recompute existing metadata eligibility under the exact native query and independently apply explicit product exclusions/documented dependency conflicts using the bound guard context. Missing facts/configuration evidence remain unknown or reference-only according to existing rules. A host preference never upgrades a card. Rejected or tampered source data is an integrity failure, not a semantic exclusion.

Select primary-eligible candidates first, then reference-only candidates, preserving host decision order within each group. Both classes are visible in the source-bound preview before selection. This pack ordering never changes the official complete pre-guard receipt order or its metrics; Quality separately measures survival from that actual full order, including loss caused by primary/reference packing. A poor survival result remains a failure, not grounds to reorder the receipt after inference. Emit at most `min(query.max_cards, pinned_policy.limits.max_detailed_cards)` complete cards, subject to remaining actual bytes. Card bytes and eligibility objects retain their existing schemas and semantic checks. Each selected record carries original native `retrieval_rank`, original native `rrf_score`/matched fields and its one-based full-pool `decision_rank`. Packed ranks need not be consecutive because blocked and budget-skipped candidates remain in the full receipt. Do not assign host-order placeholder RRF or overwrite native ranks.

Every native ID occurs exactly once either in packed cards or exclusions. Exclusions retain existing metadata/availability reasons, explicit product/dependency conflicts or truthful `candidate_budget`/`context_budget`; budget omission is not a hard or semantic rejection. `ready` means every selectable candidate fits; `limited` means some selectable candidate was omitted due to a cap, with `truncated=true`. `no_eligible` has no cards and is valid only if all native candidates are independently blocked. If an eligible card cannot fit and no eligible card can be packed, return `budget_exceeded`, not fabricated no-eligible/no-match. Failures never silently produce the native control pack.

## One shared byte ledger

Use the actual compact UTF-8 serialization of the following fixed ledger, including property names, punctuation, null slots, headers, bindings and all repeated content:

`{preview_request, decision_receipt, decision_pack}`

At preview stage the receipt and pack slots are null. Derive the evidence ceiling as the minimum of native `query.max_evidence_bytes` and the pinned policy evidence ceiling; it cannot exceed the accepted 163840 bytes. Before host input, reserve enough bytes for a complete valid receipt and a minimal valid pack/exclusion envelope, accounting for replacement of null slots. Receipt size is calculable from the exact ID set and fixed headers; permutation does not change its serialized size. For a pool with an eligible candidate, the pack reservation includes the least-byte complete eligible canonical card record, its actual recomputed eligibility, full headers and truthful exclusions for every other ID. Use the full-pool maximum decision-rank digit width when sizing a not-yet-known rank. A zero-card `no_eligible` reservation is allowed only for a genuinely all-blocked pool; it cannot make an eligible pool appear affordable. Fixed-width not-yet-known digest values may be used only for size calculation, never emitted as successful binding evidence. Preview `reservation` reports those additional byte allocations. Generate projections only within the remainder. If required skeleton/reservations cannot fit, fail before host selection. The later pack is constrained by the ledger's measured residual, not a new 160-KiB phase allocation. Reservation is not a promise that 12 cards fit.

After receipt and after every tentative packed card/exclusion, serialize the complete ledger again and enforce that same ceiling. Measured ledger bytes override declared reservations; never trust a claimed byte count. Final detailed-card count is at most 12, or the lower request cap. Native result/query can remain held locally and hash-bound; if supplied to the model or duplicated in wrappers, their bytes also count against the appropriate actual envelope and are never free hidden context.

Brief remains at most 16384 bytes, targeted context at most 16384 and request at most 8192 under the pinned native allocation. Every controlled input accounts for actual serialized objects and wrappers within 204800 bytes; anything outside those three allocations counts as evidence. Preview context already inside evidence is counted there, even if it duplicates Brief fields. Total evidence is the shared ledger above, never reset by another model call or separate tool delivery. No byte/character count is an asserted token count or a host-wide context guarantee. No preview/receipt archive is added to canonical state or HTML.

## Consumers, verification and acceptance

The smallest implementation assignment is a new `plugins/myai-stackguide/scripts/recommendation_decision.py` helper plus separately assigned unit tests and an explicit shipped-skill bridge. Reuse existing trusted retrieval/snapshot/matcher/guard seams and canonical Card/eligibility contracts; do not mutate native query/result/pack builders or their trust anchors to impersonate this pack. Quality owns the prospective scorer/case mapping and model traces. No source catalog, CP-06 native generator, physical index, policy asset or installed dependency needs changing for this outer line. The installed helper can remain standard-library-only: manually validate this contract and cross-object invariants with exact trusted schema/document SHA256 constants frozen in the helper. Runtime must not locate repository `specs` paths or accept input-provided hashes as trust anchors. Offline tests validate the canonical schema and its references with the existing development validator; adding that validator to runtime is unnecessary. A later contract change requires a coordinated helper pin update and its compatibility checks.

CP-06 remains the public source/index owner. CP-09 remains the native candidate reader. C8 synthetic/native captures remain unchanged; new outer captures have an explicit separate reader and cannot enter old C8 as fabricated native results. CP-07 is the sole writer and this transient outer type is not accepted by current state schemas. CP-10 may display only validated saved structures; no browser ranking, model call or implicit persistence is added. Any later state/memo/renderer join requires its own sequential contract assignment and correction invalidation. A new Brief/context correction invalidates the preview, receipt and decision pack alongside existing downstream dependencies. Storage/presentation versions do not substitute for decision content versions.

Positive fixtures: complete sparse/unknown projections; source-field/card hash binding; complete permutation with changed preference; unchanged native ranks/scores; mixed primary/reference order; hard-guard exclusions; fewer cards under byte cap; alias/technical literal integrity; shared reservations and measured final ledger. Negative fixtures: 13 detailed cards, full-card preview injection, omitted preview ID, duplicated/missing/foreign receipt IDs, stale Brief/query/guard/contract/pins, altered displayed source text/hash, invalid field projection, all-ID skeleton overflow, independent 160-KiB phase reset, omitted exclusion, blocked candidate packed and native fallback concealed as host success. Existing native/legacy captures and immutable finalized history must remain valid and unchanged.

Contract checks use Draft 2020-12 and offline references plus runtime semantic recomputation; schema structural validation alone does not enforce hashes, bytes, per-field uniqueness, full-ID membership, order, exclusions or model behavior. Implementation is test-first under its own packet. Whole-path cold/warm time, memory and controlled bytes include local trust/projection/validation/packing; actual host call latency/tokens/cost are reported separately and included in user-visible end-to-end latency. Unknown measurement is explicit, not zero or a waived gate.

Quality/Product must freeze the successor method and official full candidate order as the actual `decision_order` before acceptance model runs. Compare that full permutation, the native control and the unchanged original literal comparator on the same frozen goals/grades/thresholds/caps; separately report guarded packed survival and hard violations. Existing failed native/semantic captures are immutable. All exposed suites are regression evidence; a fresh prospective suite, actual compliant host trace and human calibration remain necessary. No grade/oracle enters host input, no mandatory floor is relaxed, no failed native metric is called passing. If an owner requires the native raw floor as an additional independent gate, it stays required; this outer route cannot silently waive it. Product/Quality must resolve any such meaning conflict before claiming closure.

The existing user assignment covers bounded local implementation and comparison. Sequential Architecture/Product/Quality technical acceptance is required for the new path and evaluator mapping; it is not a new external-write permission request. A waiver of an explicit owner gate, raised caps, new provider/cost/privacy boundary, installation, external write or release needs its actual separate approval. This specification supplies neither activation nor human acceptance.

Rollback disables/removes only the assigned outer helper/skill/capture differences after checking shared work. Preserve the native tuple, catalog, failed captures, existing valid state and immutable history. Native control can be delivered explicitly as native control; it cannot mask a failed or missing host decision. Future breaking outer keys/semantics require a new outer version and new schema/document hash pins; no silent upgrade of old receipts.
